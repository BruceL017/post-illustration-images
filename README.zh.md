# 文章配图生成

给公众号 / 小红书 / 知乎 / 微博内容一次配齐整套插图, 从读懂正文到分镜再到 QA 全程兜底。

## 什么时候用它

**为公众号文章配图**:

我写完一篇公众号推文, 粘上正文说「帮我做几张配图」, 想让 skill 读全文, 按方法 / 流程 / 对比 / 清单等表达类型选定风格, 一张一张出。

**制作小红书组图**:

要一组封面 + 正文轮播, 希望整套视觉统一、每张只承载一个核心含义, 按内容锚点排出分镜再逐张出图。

**使用指定风格**:

我点名 `wechat-doodle` / `xhs-explainer-notebook` / `zhihu-tech`, skill 直接省掉挑风格的问询, 按对应的 `style_file` 与 `style_spec` 出图。

**按段落安排配图**:

我按段落说「这段要一张流程分解图, 那段要一张常见错误图」, skill 按内容锚点排分镜, 一图一意, 数量不够也不硬凑。

**续做与补 logo**:

上次跑完的图想补 logo / 加一张 / 单张重跑, 只动指定的那一张, 不重跑整套。

**不接**:

纯摄影 / 人像修图 / 产品渲染 / 写实品牌大片 → 不触发; 图内要放整段精确长文 → 不触发 (图像模型画不稳); 明确点名走另一个图像 skill → 让那个 skill 接。

## 它会产出什么 / 你会看到什么

**默认一次只生成一张图, 整套统一风格靠 `style_spec` 兜底, 品牌 logo / 页码 / 占位框绝不由图像模型画**——这三点最反常识。

- **落盘位置**: `post-illustration-output/<正文短名>/` 落到项目根目录, 绝不写进 skill 目录
- **完整生产运行产出**: `shot-list.md` (分镜) + `prompts/*.md` (每张一份 prompt) + `manifest.md` (后端、模型、尺寸与 QA 元数据 YAML)
- **图片路径**: `images/unbranded/*.png` (未叠 logo 的原图) + `images/branded/*.png` (叠完 logo 的成图); 用户明确关闭品牌时原图放 `images/source/*.png`, 最终化图片放 `images/*.png`
- **最终化副作用**: 会跑 `scripts/apply-brand-overlay.mjs` 统一最终画布并按需叠加品牌; 品牌开启和关闭两种模式都依赖 `rsvg-convert`
- **生成几何**: 内置样式自动映射到合法的 `gpt-image-2` 请求尺寸; 宽高比落在容差内的返回自动归一化, 不询问尺寸
- **QA 循环**: 单张失败最多重跑 2 次, 仍不过则退回内容锚点调整, 或征得你同意后留 `residual_risk` 交付
- **绝不会做**: 让图像模型画 logo / TF / 水印 / 页码框; 一次生成整套轮播; 复制 `style_reference` 的画面语义

## 前置条件 / 边界

**前置**:

存在已验证的运行时原生图像工具或已配置 API 生图后端; 目标平台是公众号 / 小红书 / 知乎 / 微博; 机器上要有 `rsvg-convert` 以确定性输出最终尺寸。用户声明已配置 API 后端时, 预检不得转去公共 key 配置, 也不得猜测官方端点。

**不接的场景**:

- 摄影 / 人像修图 / 产品渲染 / 写实品牌大片
- 图内必须精确放整段长文 (图像模型不稳)
- 显式要求路由到另一个图像生成 skill

**微妙边界**:

- 你说「给我做 5 张」: 5 是**上限而非配额**, 内容锚点不够宁可少交也不硬塞凑数图
- `style_reference` 是 QA 用的**长期基线图**, 绝不作为生成输入, 也不复制其画面语义
- 品牌状态按“用户显式选择 > 模板默认值 > 旧模板默认开启”解析; 每份模板仍保留合法槽位, 便于运行时临时开启
- 续做单张: 只动指定图, 不重跑整套; 无原图作底时会问你是否接受在成图上重复贴 logo 的风险
